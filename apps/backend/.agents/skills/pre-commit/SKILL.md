# Проверка перед коммитом

Порядок жёсткий: сначала автоматика, потом то, что автоматика не ловит.

Рабочий каталог для относительных путей и команд — `apps/backend/`. Если Codex
запущен из корня репозитория, сначала перейди туда или передай инструменту этот
каталог как рабочий.

## 1. Автоматические проверки

```bash
make check   # ruff format --check, ruff check, mypy, lint-imports
make test    # pytest с покрытием + отдельный порог на app.kernel (85%)
```

Обе обязаны быть зелёными. **Тестам нужен запущенный Docker**: они поднимают
настоящие Postgres, RabbitMQ, Redis и MinIO через testcontainers, потому что
шаблон опирается на `JSONB`, `SKIP LOCKED`, `ON CONFLICT` и подпись SigV4 — на
другом диалекте зелёный прогон не значил бы ничего. Если Docker не поднят,
`make test` упадёт на старте контейнеров, и это не повод пропустить шаг: скажи
об этом прямо, а не отчитывайся об успехе.

Схема менялась — добавь третью:

```bash
uv run alembic upgrade head && uv run alembic check
```

`alembic check` обязан быть чистым, а `downgrade()` — написан.

## 2. Что автоматика не ловит

Пройди по списку и ответь на каждый пункт, который относится к изменению.
Молчаливое «наверное, нормально» здесь не годится — половина этих правил
помечена в проекте как «проверяется ревью» именно потому, что линтера для них
не существует.

1. **Новый модуль?** Строка в `MODULES`, `AGENTS.md` модуля на месте,
   тесты модуля есть.
2. **Новая настройка?** Поле в Settings-классе **и** строка в `.env.example` с
   объяснением, зачем она и чем грозит неудачное значение. Дефолт в коде
   совпадает с `.env.example`.
3. **Новая ручка на запись?** Решено осознанно, нужен ли ей `@idempotent`.
   GET и DELETE не помечаются.
4. **Новый побочный эффект?** Решено осознанно, `emit()` или `after_commit`.
   Ориентир: если на вопрос «а если этот эффект не случится?» ответ длиннее
   одного слова — нужен `emit()`.
5. **Новая пагинируемая таблица?** Индекс `(created_at DESC, id DESC)` создан
   миграцией.
6. **Модуль ходит наружу?** Сторож «внешний I/O вне транзакции» скопирован в
   тесты модуля — образец `tests/test_storage.py::test_s3_calls_never_happen_inside_a_transaction`.

## 3. Сам коммит

- `git status` перед `git add`. `git add -A` вслепую — нет: в коммит не должно
  попасть ничего постороннего.
- Один коммит — одно логическое изменение. Рефакторинг не смешан с фичей.
- Дальше — скилл `git-commit`.

## Если проверка упала

Не чини симптом. Найди правило, которое нарушено, и прочитай его: правила
лежат в `.agents/rules/`, а соответствие путей правилам перечислено в
`AGENTS.md` backend.
Соответствие «правило → проверка», в обе стороны, — в
`references/rule-to-check.md`; читай его, когда нужно понять, что именно
сторожит упавший тест, или наоборот — каким тестом проверить конкретное
утверждение.
