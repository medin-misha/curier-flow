# Courier Flow

CRM чешских курьерских флотилий: лиды, договоры, автопарк, расходы и
Telegram-уведомления для Bolt, Foodora и Wolt.

## Область задачи

Читай AGENTS только затронутых областей, если они ещё не загружены:

| Область | Каталог и инструкции |
| --- | --- |
| Backend | [apps/backend](apps/backend/AGENTS.md) |
| Public landing и заявка | [apps/frontend-site](apps/frontend-site/AGENTS.md) |
| Admin/Courier UI | [apps/frontend-admin](apps/frontend-admin/AGENTS.md) |
| Telegram worker | [apps/telegram-bot](apps/telegram-bot/AGENTS.md) |
| Контейнеры и окружение | [infra](infra/AGENTS.md) |

Для существующего backend-модуля дополнительно читай его `AGENTS.md`.
Командам явно задавай рабочий каталог сервиса. Для обнаружения локальных
skills начинай сессию в нужной области; один `cd` не перезагружает контекст.
Межсервисные задачи координируй из root, интеграцию проверяй через `infra/`.

## Общие правила

- Комментарии и документация — по-русски; имена кода, ключи логов и топики —
  по-английски.
- Контейнерами управляй только через `infra/`; команды: `make -C infra help`.
- Коммит — одно логическое изменение; разные сервисы объединяй только при
  общей причине. Для коммита используй skill `git-commit`.
- Уже загруженные инструкции не перечитывай, если они не изменились.
  Из rules/references выбирай только относящиеся к задаче.

При изменении инструкций или добавлении сервиса читай
[сопровождение контекста](docs/agent-context.md).
