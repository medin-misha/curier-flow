# Модуль `health`

Перед работой прочитай корневой `AGENTS.md` и `apps/backend/AGENTS.md`:
локальный файл дополняет их, но не рассчитывай на автоматическое объединение.

Три read-only ручки о состоянии сервиса: `/health/live`, `/health/ready` и
`/health/info`. Для любой правки модуля используй локальный skill
`health-module`; он подгрузит только нужные references.

## Обязательные инварианты

- `/health/live` не обращается ни к одной зависимости и отвечает 200, пока
  процесс способен выполнить корутину.
- `/health/ready` параллельно проверяет БД, RabbitMQ и S3, отвечает 200 или
  503 и не выбрасывает исключение наружу.
- Docker/Kubernetes liveness смотрит на `/health/live`, readiness — на
  `/health/ready`.
- Проверки только читают; health-модуль ничего не исправляет и не запускает в
  фоне.
- Клиенты зависимостей создаются в lifespan, но их недоступность не должна
  ронять старт приложения.
- Ответ readiness не кешируется; `/health/info` не раскрывает секреты и в
  production закрывается на периметре.

В модуле намеренно нет моделей, request-схем, событий, подписчиков и задач. Не
создавай пустые файлы для симметрии.

Проверка: `uv run pytest tests/test_health.py -v` из `apps/backend/`.
