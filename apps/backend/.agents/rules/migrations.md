# Миграции

- схема меняется только миграцией: `make revision m="..."`, затем **прочитать
  сгенерированный файл** — autogenerate не видит переименований и путает их с
  «удалить и создать»;
- имя ревизии — по дате и смыслу, как у существующих
  (`20260809_2034_files_table.py`);
- `downgrade()` обязан возвращать базу к прежнему состоянию: изменённую ревизию
  локально проверяют циклом `downgrade -1` → `upgrade head` на отдельной базе
  без ценных данных;
- модели и миграции не имеют права разъезжаться;
- таблицы из `tests/models.py` в миграции не попадают: это полигон тестов ядра,
  он создаётся отдельным `create_all` по явному списку.

**Проверяют:** `uv run alembic check` (расхождение моделей и миграций),
`uv run alembic downgrade -1 && uv run alembic upgrade head` (откат изменённой
ревизии); полный локальный порядок задают скиллы `db-migration` и `pre-commit`.
`tests/conftest.py` строит схему прогона именно миграциями, поэтому сломанная
цепочка роняет `make test`.

Порядок действий при изменении схемы — скилл `db-migration`.
