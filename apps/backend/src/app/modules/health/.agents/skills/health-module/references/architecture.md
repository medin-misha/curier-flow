## Устройство

```
handlers.py            # только HTTP: собрать ответ, выставить статус и заголовки
services.py            # вся логика: проверки, таймауты, чтение ревизии
schemas/responses.py   # контракт ответов
module.py              # манифест Module + lifespan с клиентами проверок
```

- `handlers.py` не знает ни про aio-pika, ни про botocore: он получает `Probes`
  из `app.state` и передаёт их сервису.
- `services.py` не создаёт клиентов — они приходят аргументом. Соединение с
  брокером и клиент S3 создаёт `Module.lifespan` один раз на процесс:
  readiness опрашивают раз в несколько секунд, и соединение на каждый опрос
  стоило бы дороже самой проверки.
- Приложение обязано подниматься при лежащем брокере или хранилище. Если
  падение зависимости уронит старт, readiness не сможет о нём доложить.
  Соединение с брокером восстанавливается лениво при очередной проверке.
- Псевдоним `RoSession` объявлен в `handlers.py`, а не взят из `app.api.deps`:
  правило зависимостей `api → modules → platform → kernel` запрещает модулю
  импортировать слой api.
