# Добавление велосипеда

Велосипеды лендинга добавляются данными, без правок компонентов и движка
скролла. Команды ниже выполняются из `apps/frontend-site/`.

## 1. Подготовить ассеты

Ассеты экспортируются и копируются вручную. Автоматического импорта,
транскодирования или проверки медиа в проекте нет; исходные соответствия
описаны в [README каталога public](../public/README.md).

Для уникального стабильного `<slug>` создай каталог:

```text
public/bikes/<slug>/
├── poster.png
└── loop.mp4
```

- `poster.png` обязателен. В данных он доступен как
  `/bikes/<slug>/poster.png` и служит самостоятельным изображением или постером
  для видео.
- `loop.mp4` использует текущую файловую конвенцию MP4, но поле видео
  опционально. Если видео нет, не создавай файл и не задавай `media.video`.
- Имена файлов и регистр должны точно совпадать с URL в данных.
- Фиксированного разрешения код не требует. Медиа заполняет сцену через
  `object-fit: cover`, поэтому проверь качество и кадрирование на узком и
  широком экране.
- Проект не проверяет кодек внутри MP4. Убедись в браузере, что готовый файл
  воспроизводится; при отказе autoplay или ошибке видео постер должен оставаться
  пригодным фоном.

Не импортируй файлы в TypeScript: Next.js раздаёт содержимое `public/` от корня
сайта. Не заменяй текущие `<img>` и `<video>` на `next/image` без отдельной
проверки пиксельной графики.

## 2. Добавить запись каталога

Добавь объект в нужную позицию массива `bikes` в `src/content/bikes.ts`. Под
`BikeContent` в этом workflow понимается контентная запись велосипеда; текущее
имя её TypeScript-типа в коде: `Bike` из
`src/features/landing/scene.types.ts`.

```ts
{
  slug: 'cargo-x2',
  name: 'MFS Cargo X2',
  media: {
    poster: '/bikes/cargo-x2/poster.png',
    video: '/bikes/cargo-x2/loop.mp4',
    focus: '55%',
  },
  specs: [
    { label: 'АКБ', value: '48V · 30Ah', note: 'зарядка 6 часов' },
    { label: 'ЗАПАС ХОДА', value: 'до 90 км', note: 'на одном заряде' },
  ],
  description: ['Описание велосипеда и условий выдачи.'],
  price: { amount: 'от 2400 CZK', period: 'в неделю' },
},
```

Поля записи:

- `slug`: уникальная часть путей ассетов и производного ID сцены
  `bike-<slug>`. Используй стабильный lowercase kebab-case без пробелов.
- `name`: имя активного велосипеда в шапке.
- `media.poster`: обязательный URL постера от корня сайта.
- `media.video`: опциональный URL MP4. Источник подставляется только после
  первого показа сцены и затем не выгружается.
- `media.focus`: горизонтальный `object-position`, обычно процент вроде `55%`;
  вертикальная позиция остаётся по центру.
- `specs`: tuple ровно из двух объектов `Spec`. Каждый содержит `label`,
  `value` и `note`; рендер раскладывает элементы в левый и правый блок.
- `description`: массив абзацев. Каждый элемент выводится отдельным `<p>`.
- `price.amount` и `price.period`: части строки стоимости аренды.

Не добавляй третью характеристику без намеренного редизайна типа и раскладки.
Не добавляй `BikeScene` вручную и не меняй discriminated union `Scene`:
`composeScenes()` преобразует все элементы `bikes` через `toBikeScene()`.
Порядок объектов в `bikes` определяет порядок велосипедных сцен.

## 3. Проверить автоматические производные

После изменения только `src/content/bikes.ts` должны автоматически обновиться:

- число сцен и высота scroll track;
- точка прогресса для новой сцены;
- позиционная нумерация следующих подписей, включая экипировку, и номер секции
  контактов в футере;
- цель секции «Сумки» после всех велосипедов;
- активное состояние «Транспорт» на каждой велосипедной сцене;
- имя активного велосипеда в шапке;
- переход «Назад к велосипеду» из экипировки на последний велосипед.

Сцена появится после трёх intro-сцен и перед экипировкой. Не дублируй эти
производные числа или индексы в компонентах. Отдельный пункт меню для каждого
велосипеда не создаётся: «Транспорт» ведёт на первый велосипед и остаётся
активным на всех велосипедных сценах.

## 4. Выполнить focused checks

Сначала запусти тесты, непосредственно покрывающие каталог, рендер и производные
скролла:

```bash
npm test -- src/content/scenes.test.ts src/features/landing/scenes/BikeScene.test.tsx src/features/landing/ScrollStage.test.tsx
```

Если менялся только объект данных, отдельный компонент или новый вид сцены не
нужен. Затем выполни обязательные проверки проекта:

```bash
npm run typecheck
npm test
npm run build
```

В `package.json` нет lint-скрипта и нет asset pipeline, поэтому не подменяй эти
команды несуществующими `lint`, `assets` или `e2e`.

## 5. Выполнить browser QA

Запусти `npm run dev` и проверь `/` средствами Playwright MCP или вручную в
браузере. Для этого проекта browser QA не заменяется jsdom-тестами.

- На мобильном и desktop viewport проскролль все сцены в обе стороны. Отдельно
  проверь поведение около CSS breakpoint `768px`.
- Проверь кадрирование постера и видео; скорректируй только `media.focus`, если
  объект смещён по горизонтали.
- Убедись, что новый `name`, обе характеристики, все абзацы и цена читаются и
  не перекрываются шапкой, CTA, точками или соседней сценой.
- Проверь число точек, нумерацию, переходы меню, высоту скролла и возврат из
  экипировки на последний велосипед.
- В Network и Console не должно быть `404`, ошибок декодирования медиа или
  React-ошибок. Заблокируй видео или проверь вариант без `media.video`, чтобы
  подтвердить постерный fallback.
- Пройди интерактивные элементы клавиатурой. Bike-scene не должна добавлять
  собственных фокусируемых элементов; известное ограничение семантики скрытого
  bike-контента описано в [known gaps](known-gaps.md).
- Включи `prefers-reduced-motion: reduce`: CSS-переходы должны стать практически
  мгновенными, а контент должен остаться видимым. Автовоспроизведение видео пока
  не отключается этой настройкой и считается известным ограничением.
- Важная информация должна оставаться в тексте, а не только в декоративном
  медиа: статический постер рендерится с пустым `alt`, видео не имеет отдельного
  доступного описания.
