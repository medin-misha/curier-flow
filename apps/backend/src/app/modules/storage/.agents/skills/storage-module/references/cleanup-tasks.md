## Задачи

| Задача                            | Расписание                    | Что делает                          |
| --------------------------------- | ----------------------------- | ----------------------------------- |
| `storage.sweep_orphaned_uploads`  | `STORAGE_ORPHAN_SWEEP_CRON`   | `pending` старше TTL → объект и строка |
| `storage.delete_marked_files`     | `STORAGE_DELETION_INTERVAL`   | `deleting` → объект и строка        |

Инварианты, которые нельзя нарушать при правке:

- **Сначала объект, потом строка.** В обратном порядке сбой между шагами теряет
  объект навсегда: ключ хранится только в строке.
- Сборщик сирот сперва помечает строки `deleting` отдельной транзакцией
  (`UPDATE ... WHERE id IN (SELECT ... FOR UPDATE SKIP LOCKED)`), и только
  потом идёт удалять. Пометка отбирает строку у гонки: опоздавшее
  подтверждение уже не сделает готовым файл, объект которого вот-вот удалят.
- Отказ по одному файлу не прекращает проход: строка остаётся `deleting` и
  попадёт в следующий.
- Задачи создают клиент хранилища на каждый запуск: `lifespan` модуля
  поднимает только приложение FastAPI, воркер его не исполняет.
