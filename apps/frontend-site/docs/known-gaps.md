# Границы интеграции

Backend не изменялся. `POST /courier` принимает multipart `payload` + `files`,
создаёт документы в private S3 и возвращает 201 либо существующую анкету с 200.
Повтор не обновляет её и не добавляет файлы. Поля выбора транспорта в API нет;
по согласованию с пользователем оно удалено, транспорт согласует менеджер.
Ответ «Откуда узнали» сохраняется в `source` (не более 64 символов).

## Документы и персональные данные

Сервер проверяет заявленный MIME, ненулевую длину и фактический размер потока;
проверки сигнатуры содержимого/антивируса нет. Доступ к чтению документов
требует admin JWT. Публичный POST не требует авторизации. Клиентские проверки
не заменяют серверную защиту.

Документы отправляются с целью `platform_onboarding`; текущий backend по
умолчанию использует retention 90 дней, фоновую очистку и legal hold. Реальный
срок зависит от настроек и работы worker. Форма не обещает фиксированный срок.
Полная юридическая privacy policy должна быть утверждена владельцем продукта;
в форме есть фактическое пояснение передачи данных и контакт для запросов.

Интеграционная проверка использует только синтетические данные и файлы.
Живой тест создаёт одну анкету с `source=frontend-site-e2e`; она остаётся в БД
для проверки в админ-панели. Тест не удаляет пользовательские записи.
