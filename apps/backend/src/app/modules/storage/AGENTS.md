# Модуль `storage`

Модуль хранит метаданные файлов и выдаёт presigned URL; содержимое ходит между
клиентом и S3 напрямую. Для любой правки используй локальный skill
`storage-module`; он выберет нужные references.

## Обязательные инварианты

- Backend не принимает и не проксирует байты файлов.
- Внешний I/O не выполняется внутри транзакции: чтение БД → закрытие сессии →
  S3 → короткая пишущая транзакция.
- Жизненный цикл однонаправленный: `pending → ready` или
  `pending/ready → deleting`; из `deleting` возврата нет.
- `confirm` меняет статус на `ready` в одной транзакции с
  `emit(FileConfirmed)`.
- Удаление выполняет задача: сначала объект в S3, затем строка БД.
- `kiq()` из HTTP-ручек запрещён; уборка основана на состояниях таблицы и
  периодических задачах.
- Presigned URL подписывается сразу для публичного host; host готовой ссылки
  не заменяется.
- Клиент не задаёт `key`, `owner_id` и статусы.

Основная проверка: `uv run pytest tests/test_storage.py -v` из
`apps/backend/`.
