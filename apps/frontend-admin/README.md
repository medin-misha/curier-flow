# MFS Frontend Admin

Vue 3-панель для работы с реестром курьеров May Fleet Solutions. Панель
аутентифицирует администратора и работает с существующими Admin и Courier API.

## Запуск в Docker Compose

Единственная точка управления контейнерами находится в `infra/`:

```bash
make -C infra up
make -C infra caddy-ca
```

Админка откроется по адресу `https://admin.localhost`. Caddy завершает TLS, а
nginx внутри frontend-контейнера сохраняет same-origin контракт и проксирует
API по внутреннему адресу `http://api:8000`. Не задавайте `VITE_API_URL` для
Compose-сборки: refresh cookie привязана к `admin.localhost`.

Root CA для доверия локальным сертификатам экспортируется в
`infra/secrets/caddy-root.crt`; процедура установки описана в backend README.

## Отдельный Vite dev-сервер

```bash
cd apps/frontend-admin
npm install
npm run dev
```

Vite откроет приложение по адресу `http://127.0.0.1:5173`. Этот режим не входит
в стандартный Compose-стек: его proxy ожидает отдельно доступный API на
`http://127.0.0.1:8000`, тогда как Compose публикует API только через Caddy.

Если API публикуется на отдельном origin и окружение разрешает такие запросы,
его можно задать во время сборки:

```bash
VITE_API_URL=https://api.example.com npm run build
```

Для refresh-сессии предпочтителен same-origin reverse proxy, сохраняющий пути
`/admin/auth/*`: backend устанавливает HttpOnly cookie с
`Path=/admin/auth`.

## Проверка

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

Команда `npm run preview` запускает собранную версию по адресу
`http://127.0.0.1:4173`.

## Текущие возможности

- вход, восстановление refresh-сессии и выход администратора;
- автоматическое обновление access JWT после ответа `401`;
- точный поиск, фильтрация по статусу и keyset-пагинация реестра;
- адаптивное представление таблицы;
- просмотр профиля, изменение статусов платформ и скачивание документов курьера;
- создание курьера и опционального документа через multipart API;
- редактирование и удаление курьера;
- выбор до 100 курьеров между страницами, массовое удаление и смена статуса платформы;
- состояния загрузки и ошибки API;
- управление модальными окнами с клавиатуры.

Access JWT хранится только в памяти приложения. Refresh-токен недоступен
JavaScript и передаётся backend только через HttpOnly cookie.

## Контракт массовых операций Courier API

| Операция | Запрос JSON | Ответ `200` |
| --- | --- | --- |
| `POST /courier/bulk-delete` | `{ "courier_ids": ["UUID", "UUID"] }` | `{ "deleted_count": 2 }` |
| `PATCH /courier/bulk-status` | `{ "courier_ids": ["UUID", "UUID"], "platform": "wolt", "status": "active" }` | `{ "updated_count": 1, "unchanged_count": 1 }` |

Оба запроса требуют Admin access JWT в `Authorization: Bearer …` и заголовок
`Idempotency-Key`. Допустимы от 1 до 100 уникальных UUID. Для платформы доступны
`bolt_food`, `foodora`, `wolt`; для статуса — `pending`, `active`, `inactive`.
Статус принадлежит регистрации на выбранной платформе. Другие регистрации
не меняются, отсутствующие не создаются. Фильтр списка `GET /courier?status=…`
выбирает курьеров с хотя бы одной регистрацией в указанном статусе.

Операции синхронны и атомарны: ошибка одного курьера откатывает всю выборку.
Ошибки возвращаются в формате Problem Details:

- `404`, `courier_ids`: отсутствующие курьеры;
- `409`, `reason=platform-account-missing`, `platform`, `courier_ids`: нет регистрации;
- `409`, `reason=signed-contract-protects-rental`, `courier_id`: удалению мешает подписанный договор аренды;
- `422`: пустой или слишком большой список, дубликаты UUID, неверная платформа или статус;
- `409`, `reason=payload-mismatch`: тот же ключ использован с другим телом запроса.

Повтор с тем же ключом и телом возвращает исходный ответ и счётчики. Frontend
сохраняет ключ при ошибке, в том числе при потере сетевого ответа и повторной
авторизации; изменение параметров получает отдельный ключ. После успешной
операции ключи сбрасываются. Физическая очистка файлов после удаления асинхронна.

В интерфейсе «Выбрать страницу» отмечает только текущую страницу. Выбор
сохраняется при пагинации, применение поиска или фильтра его сбрасывает.
Перед отправкой показывается полный список выбранных курьеров. При ошибке
форма и выбор сохраняются. После успеха выбор очищается, а реестр загружается
с первой страницы с применёнными фильтрами; счётчики результата берутся из API.
