# Сопровождение контекста агента

Читай этот документ при изменении AGENTS/skills и добавлении сервиса.

## Загрузка

Codex собирает AGENTS от root до рабочего каталога при запуске сессии;
смена каталога отдельной команды не пересоздаёт эту цепочку. Для клиентов,
которые загружают только ближайший AGENTS, ссылки на родительские правила
остаются обязательными. Уже загруженный неизменённый текст повторно не читай.

Project skills находятся в `.agents/skills/` по пути от рабочего каталога до
корня worktree. На старте нужны только их метаданные; полные инструкции и
references читаются при соответствующей задаче.

## Где хранить знания

- AGENTS: область, критические инварианты, команды и выбор нужного контекста.
- SKILL: повторяемый порядок работы и точные условия чтения references.
- References: детали отдельного сценария; одна каноническая формулировка.
- Backend rules: общая политика в `apps/backend/.agents/rules/`.
- Scripts: детерминированные операции вместо повторения команд в инструкциях.

Не дублируй каталоги, длинные примеры или общую политику. Короткое напоминание
критического ограничения в AGENTS допустимо. Не дроби справочник на файлы,
которые всегда читаются вместе. Сохраняй существующие security-инварианты.
Проверки текущего состояния засчитываются между skills без повторного запуска.

## Бюджеты и проверка

`bash scripts/check-agent-context.sh --report` печатает UTF-8 байты и лимиты:

- root AGENTS: 2304 байта;
- root + service: 7 KiB;
- root + backend + module: 8 KiB;
- SKILL: 6 KiB; description: 512 байт.

Команда без `--report` выполняет те же проверки без таблицы размеров.
Проверяются наличие модульных инструкций, метаданные skills, локальные
Markdown-ссылки в контексте и отсутствие устаревших путей.

`scripts/agent-context-scenarios.tsv` задаёт фиксированные наборы чтения для
сравнения: frontend, storage, защита ручки и фоновая задача. Общие файлы
внутри сценария учитываются один раз. Это статический бюджет инструкций,
а не измерение всего prompt, токенов или времени. При изменении маршрутизации
обновляй наборы: произвольную цепочку естественного языка скрипт не выводит.

Для оценки скорости сравнивай одинаковые реальные задачи в свежих сессиях:
прочитанные файлы, входные токены (по доступной статистике клиента), число
вызовов и время. Отдельно учитывай глобальные инструкции и метаданные plugins;
они не входят в этот репозиторий и не отключаются его AGENTS.

## Новый сервис

1. Добавь `apps/<service>/AGENTS.md`: ссылка на root, команды и инварианты.
2. Зарегистрируй область в root AGENTS; проверка автоматически найдёт сервис.
3. Service skills создавай только для повторяемого workflow.
4. Для нового типового сценария добавь бюджет в TSV и запусти проверку.

Новый backend-модуль всегда получает собственный AGENTS; инструкция создания
находится в `new-module/references/module-context.md` внутри backend skills.

## Замер после оптимизации, 2026-09-16

Размеры фиксированных наборов из TSV, UTF-8 байты. Исходная версия учитывает
обязательное чтение всего auth-механизма и всех трёх правил фоновых эффектов.

| Набор | До | После | Сокращение |
| --- | ---: | ---: | ---: |
| Frontend AGENTS | 8510 | 6600 | 22% |
| Storage: AGENTS, skill, endpoints, checklist | 15744 | 11513 | 27% |
| Storage + защита ручки | 33512 | 19416 | 42% |
| Storage + фоновая задача | 40988 | 21768 | 47% |

Root + backend отдельно: 9389 → 5234 байта (44%). Это измерение объёма
инструкций; скорость выполнения и токены реальной сессии не измерялись.
