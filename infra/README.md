# HTTPS и публичный доступ

Все контейнеры управляются из `infra/` через `make`; список команд — `make help`.
Для проверок нужны Docker с Compose v2, Make, curl и стандартные awk/printf.

## Домены

`PUBLIC_DOMAIN` в `infra/.env` задаёт базовый домен без схемы, порта и пути.
По умолчанию это `localhost`: локальные адреса и CA Caddy сохраняются. Для
публичного сервера с IP `34.27.210.24`:

```dotenv
PUBLIC_DOMAIN=34-27-210-24.sslip.io
DEBUG=false
S3_PUBLIC_ENDPOINT_URL=https://minio.${PUBLIC_DOMAIN:-localhost}
```

| Сервис | URL для этого сервера |
| --- | --- |
| Сайт | `https://34-27-210-24.sslip.io` |
| Admin/Courier UI | `https://admin.34-27-210-24.sslip.io` |
| Backend API | `https://backend.34-27-210-24.sslip.io` |
| Grafana | `https://grafana.34-27-210-24.sslip.io` |
| MinIO S3 API | `https://minio.34-27-210-24.sslip.io` |

`sslip.io` автоматически возвращает IP из имени: регистрация домена и ручные
DNS-записи не нужны. Это DNS, не туннель; IP сервера следует закрепить как
статический. При его смене придётся изменить домен и заново войти в Admin.

Caddy получает отдельные публично доверенные сертификаты через ACME и продлевает
их автоматически. Certbot, DNS API token и wildcard-сертификат не нужны.
`localhost` и его поддомены используют локальный CA; установить доверие к нему
нужно только для локального режима (`make caddy-ca`). В публичном режиме
localhost-алиасы не добавляются.

## Перед публикацией

- DNS всех пяти имён должен указывать на сервер. В облачном и хостовом firewall
  разреши входящие `80/TCP` и `443/TCP` до Caddy; `443/UDP` нужен только для HTTP/3.
  Для ACME также нужны исходящий HTTPS и рабочий DNS. При NAT настрой проброс.
- Проверь, что порты 80/443 не заняты другим ingress. Только Caddy публикует HTTP;
  PostgreSQL, RabbitMQ (включая management) и Redis привязаны к `127.0.0.1`.
  Для удалённого администрирования используй SSH-туннель или VPN, а не открытые
  порты БД. Доступ SSH в firewall сохрани.
- Отключи `DEBUG`, замени шаблонные секреты и пароли, оставь вход в Grafana
  обязательным. Для production используй `APP_ENV=prod`; публичный staging может
  оставаться `staging`. Смена пароля в `.env` не меняет пароль уже созданного
  PostgreSQL/RabbitMQ/Admin: ротация существующих credentials — отдельная операция.
- Защита от перебора Admin-паролей и спама заявок должна быть настроена отдельно
  на внешнем периметре: штатный образ Caddy не добавляет rate limiting. Учти вход
  `/admin/auth/login` на доменах Admin и Backend, а заявки — `/api/courier` на
  сайте и `/courier` на доменах Admin/Backend.
- HTTPS не устраняет [известные пробелы формы и обработки персональных данных](../apps/frontend-site/docs/known-gaps.md).
  Сам по себе этот deployment не означает готовность к сбору реальных документов.

## Контракт маршрутизации

Внутренние upstream остаются HTTP по Compose-именам. Сайт использует Next.js
rewrite, Admin — same-origin nginx proxy: менять frontend API URL и backend
CORS не требуется. Refresh cookie остаётся `Secure`, `HttpOnly`, host-only;
вход, refresh и logout выполняются на одном Admin-домене.

`S3_PUBLIC_ENDPOINT_URL` должен совпадать с HTTPS-доменом MinIO в Caddy: SigV4
подписывает `Host`, поэтому заменять домен в готовой ссылке нельзя. Compose
раскрывает `${PUBLIC_DOMAIN:-localhost}` в `.env`; shell-переменные имеют приоритет.
MinIO разрешает браузерные CORS-запросы только с сайта и Admin этого домена.
Доступ к объектам по-прежнему требует подписи, CORS не заменяет авторизацию.

В публичном режиме через Caddy закрыты `/health/ready`, `/health/info`, Swagger/OpenAPI Backend,
`/metrics` Grafana и служебные `/minio/*`, кроме `/minio/health/live`. Внутренние
healthcheck и мониторинг продолжают обращаться к сервисам напрямую. MinIO console
не публикуется; S3-пути нельзя закрывать дополнительной Basic Auth, иначе
подписанные браузерные загрузки перестанут работать.

При `PUBLIC_DOMAIN=localhost` диагностические маршруты остаются доступны как
раньше, а Swagger/OpenAPI зависит от `DEBUG`. Такой режим не предназначен для
интернет-публикации: локальный сертификат сам по себе не ограничивает доступ.

## Применение и проверка

Из `infra/` после обновления `.env`:

```bash
make check
make reboot-infra
make smoke-caddy
make ps
```

`reboot-infra` последовательно пересоздаёт стек, чтобы применить loopback-привязки
портов и MinIO CORS. Будет краткий простой. Данные, локальный CA и публичные
сертификаты сохраняются в volumes. Для дальнейшей смены только домена достаточно
`make up-infra`, `make reboot-logging`, `make reboot-apps` в этом порядке.
Не используй `delete*` для смены домена или исправления TLS.

`make check` проверяет Compose, Caddy с текущим доменом и контекст агента; для
отдельной проверки локального режима выполни `PUBLIC_DOMAIN=localhost make check`.
Валидация не выпускает публичный сертификат. Caddy может стать healthy раньше
завершения ACME: дождись выдачи сертификатов и повтори `make smoke-caddy`.

`smoke-caddy` проверяет пять HTTPS-маршрутов, редиректы и, в публичном режиме,
закрытую диагностику.
Для публичного домена используется системное доверие, без `curl -k` и без
экспорта локального CA. Если ACME не проходит, проверь DNS, доступность портов и
логи Caddy; не удаляй volume и не повторяй выпуск бездумно — у CA есть лимиты.

После сетевой проверки проверь в браузере сайт и Admin, вход и обновление сессии,
вход в Grafana, загрузку и скачивание тестового файла через подписанные HTTPS URL.
Тестовый файл удали. Токены, cookies и подписанные URL не публикуй в логах проверок.
